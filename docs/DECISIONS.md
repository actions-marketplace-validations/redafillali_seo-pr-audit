# Décisions

- **Phase 0** — `@eslint/js` ajouté en devDependency : requis par la flat config ESLint (`js.configs.recommended`), absent de `CONCEPTION.md`.
- **Phase 0** — `@types/node` épinglé en `22` pour correspondre à `.nvmrc` ; `runs.using: node24` conservé (supporté par GitHub Actions).
- **Phase 0** — `.remember/`, `.repowise/`, `.superpowers/` ignorés par git (outillage local).
- **Phase 0** — `tsconfig.json` : `rootDir: "."` requis par TypeScript 6 (TS5011) pour que `ncc` compile.
- **Phase 1** — `zod` v4 + `yaml` ajoutés (listés dans CONCEPTION). Un clé inconnue dans `.seo-audit.yml` est une erreur (détection des fautes de frappe). `static-dir` et `base-url` sont mutuellement exclusifs ; `start-command` exige `base-url`. Un fichier de config absent est ignoré.
- **Phase 2** — `sirv` ajouté (listé dans CONCEPTION). Serveur statique lié à 127.0.0.1 uniquement. `start-command` passe par un shell (`shell: true`) pour supporter `a && b` ; il vient d'un input du workflow, jamais du contenu de PR. Fixture `long-title` : title 82 car., description 27 car. (plan : ~80 / ~30).
- **Phase 3** — `cheerio` ajouté. Une sévérité configurée (`error`/`warning`) s'applique à tous les findings de la règle ; `off` les supprime. `canonical` : « pointe vers une page indexable » implémenté ensuite dans `seo/canonical-target.ts` (même origine uniquement : le chemin du canonical est sondé sur la cible auditée, pas d'appel sortant) ; « autre domaine » compare les hostnames (port ignoré). Doublon de title : finding `title` (warning) avec `details`.
- **Phase 4** — `p-limit` ajouté. Redirections suivies manuellement (`redirect: manual`, max 10) pour compter les sauts ; >2 sauts = warning `broken-links`. Le cache stocke la promesse (un lien partagé n'est requêté qu'une fois, même en concurrence). Timeout/erreur réseau = lien cassé.
- **Phase 5** — `lighthouse` (13.5.0) et `chrome-launcher` (1.2.2) **épinglés** (versions exactes) et **exclus du bundle ncc** (`-e`). Raison : Lighthouse lit au runtime des fichiers relatifs à son propre emplacement (`locales/`, `package.json`, `report/assets`, `dist/report`, `flow-report/assets`, scan de `gather/gatherers`…) et se croit « bundlé » (esbuild `__name`) si `lighthouse-logger` n'est pas résolvable ; plusieurs tentatives de copie d'assets à côté du bundle ont échoué à chaque fois sur un nouveau fichier. Solution retenue (le « dernier recours » du plan) : installation à l'exécution via `npm install` dans `$RUNNER_TEMP` (`src/lighthouse/install.ts`, ~20 s, une seule fois, uniquement si `lighthouse: true`). Vérifié en local avec un vrai Chrome : scores 100/96/96/100 sur la fixture `/`. Un échec d'installation ou de Chrome → `core.warning`, Lighthouse désactivé, pas d'échec du job.
- **Phase 5** — Taille de `dist/` : ~3,6 Mo (bundle ~1,7 Mo + sourcemap ~2 Mo), sans Lighthouse (installé hors bundle). Conséquence : le runner a besoin d'accès réseau npm pour Lighthouse.
- **Phase 5** — `node24` : Lighthouse 13 exige Node ≥ 22.19 ; OK avec `node24`.
- **Phase 6** — Tout texte issu des pages (messages, URLs, titres) est échappé dans le Markdown (`<`, `>`, `|`, backticks, `@` → anti-mention/injection HTML). Troncature en 3 paliers sous 65 000 car. : sans sous-détails → tableau seul → coupe franche. Sans Lighthouse, le tableau n'a que les colonnes Page/Checks. Marqueur unique `<!-- seo-pr-audit:v1 -->` : le suffixe `:{job}` de CONCEPTION §7 n'est pas implémenté en v1 (un seul commentaire par PR).
- **Phase 7** — `src/audit.ts` porte le pipeline (testable sans `@actions/*` d'E/S) ; `main.ts` ne fait que config → cible → audit → publication → `finally` arrêt cible. Page non-2xx ou injoignable → `page-unreachable` (status 0 si réseau) et la page est exclue de Lighthouse. Le job summary est rendu avec une limite de 900 000 car. (1 MiB GitHub), le commentaire avec 65 000. Un 403 sur le commentaire n'échoue pas le job. Vérifié de bout en bout avec le `dist/index.js` réel + Lighthouse réel.
- **Phase 8** — Demande utilisateur : l'action commente aussi sur `push` (commentaire de commit, `contents: write`) ; autres événements : pas de commentaire, résumé/JSON/outputs conservés. Le marqueur n'est accepté que sur un commentaire d'un **Bot** (anti-détournement par un contributeur, y compris dans l'exemple `workflow_run` de `docs/forks.md`). `scripts/check-readme.ts` (exécuté en CI) compare les tables Inputs/Outputs du README à `action.yml`. `e2e.yml` s'exécute sur `pull_request` et `push` sur main. `OWNER` remplacé par `redafillali` (déjà fait).
- **Sécurité (revues automatiques)** — Corrigé : `start-command`/`base-url`/`static-dir` **refusés dans `.seo-audit.yml`** (le fichier vient du dépôt audité, donc d'une PR : exécution de commande) ; chemin hors origine de `base-url` refusé (`//evil`) ; redirection de lien vers un schéma non http(s) refusée ; `npm install --ignore-scripts` pour Lighthouse ; échappement Markdown étendu (`[ ] ( ) ! * _ ~ # \`) ; commentaire réutilisé seulement s'il vient d'un Bot. **Non corrigé (accepté)** : SSRF par redirection de liens vers réseaux privés (hors périmètre v1, `check-links: all` suit déjà n'importe quel lien) ; pas de lockfile pour Lighthouse (versions épinglées mais dépendances transitives non verrouillées).
- **Défaut `comment: false`** (demande utilisateur) : changement de comportement, donc version mineure 1.2.0. **Jokers dans `paths`** (demande utilisateur) : `/blog/*` explore par liens (BFS, même origine, HTML 2xx, sous le préfixe), plafonné par `max-pages` (50 par défaut, 500 max) ; la page de départ est toujours gardée pour que son erreur soit signalée ; les pages non liées (non trouvables par liens) ne sont pas découvertes — le sitemap reste en roadmap.
